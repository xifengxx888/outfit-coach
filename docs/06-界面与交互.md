# 06 · 界面与交互（M1）

> 对应阶段：M1。只写 M1 的界面；M2 的 B 档、M3 的课程、M4 的 C 档不在此文。
> 本文回答"每一屏放什么、怎么流转、出错怎么办"，**不定义视觉风格**。
>
> **M1 不做可点击原型。** 交互原型会成为第二套实现，改一次要改两处。规格与线框先定，视觉在真实页面里迭代。

---

## 一、原则

1. **手机竖屏优先。** 基准 390×844（iPhone 14/15），最低 360×800。所有主按钮落在屏幕下 1/3 的拇指区。
2. **一屏一个主任务。** 录入页只做录入，组合页只做判断，不叠功能。
3. **每个空状态都有出口。** 没衣服 → 去录入；没有合规组合 → 放宽结果或缺口诊断；没有地点 → 去设置。
4. **反馈永远一键。** 不弹评分、不要求写文字。最强的信号是"今天穿这套"。
5. **诚实标注。** 放宽了几档、哪件是草稿、哪项没填，必须在界面上看得见。
6. **界面验收必须截图 + 视觉检查。** 不靠读代码推断布局（全局规则）。

## 四、页面规格

### 4.1 `/setup` 首次设置

| 区块 | 内容 | 交互 |
|---|---|---|
| 地点 | 地址输入 → 候选列表（名称 + 行政区/国家）→ 确认 | 不填也能用，体感手调；之后在「我的」补 |
| 身材 | 9 项，每项一行：数值输入 + 单位 + `手量/量衣/估算` 来源 | 全部可跳过；非空值未选来源默认 `估算` |
| 完成 | [跳过] [完成] | 完成进入 `/closet`；跳过后不再自动进入向导 |

- **何时出现**：`profile` 无记录且 `location` 为空，且本次是从 `/closet` 首次进入；深链（`/today`、`/item/:id`）不被劫持。重定向用 `replaceState`，返回不会退回向导。
- 身材页必须能一屏看到全部 9 项，不强制逐项填写；每项旁边显示来源标记。
- 跳过向导 = 写入一行空 profile，之后仍可在「我的」补地点与身材。
- 地点添加时同步尝试拉近 10 年同期气候；失败不阻塞，保留实时天气能力，「我的」里可重取。

### 4.2 `/add` 录入

单页表单，不做分步向导。从上到下：照片 → 属性 → 尺寸（条件显示），底部吸底保存栏。

**照片（可选，最多 6 张）**

- 两个入口：[拍照]（`input capture="environment"`）/[从相册选]；选完可继续加，满 6 张隐藏入口并提示「最多 6 张」。
- 拍照要求：平铺、正上方、光线均匀、拍全。**M1 照片只留档，不估尺寸、不提取属性。**
- 选完在本地压缩（最长边 1600 JPEG）后进缩略图网格，右上角显示 `3/6`；**第一张标「封面」**，不分用途、不打标签。
- 待保存的新图可 [移除]；移除第一张后，下一张自动成为封面。
- 小字：「第一张作为封面；照片只留在本机，不上传第三方；不拍也能入库，衣库会显示无图。」

**属性**

| 字段 | 控件 | 必填 | 说明 |
|---|---|---|---|
| 名称 | 文本框 | 是 | 例「深蓝牛仔外套」 |
| 品类 | 单选 chips | 是 | 02 的 15 个品类 |
| 层级 | 多选 chips | 条件 | inner / mid / outer / bottom / shoes / accessory；连体装、西装套装由品类决定槽位，不显示此项 |
| 正式度 | 1–5 分段 | 是 | 运动 / 休闲 / 日常 / 商务休闲 / 正装 |
| 版型 | 分段 | 是 | 修身 / 合身 / 宽松 |
| 颜色 | 色块 + HEX + 预设 + 调色板 + 从照片取色 | 是 | 四个人口：16 个预设、系统调色板（`<input type="color">`）、从照片点选取色（5×5 平均）、手填 HEX；无默认值，未选时显示「未选」；无照片时「从照片取色」禁用 |
| 图案 | 分段 | 是 | 纯色 / 细纹 / 大图案 |
| 厚度 | 分段 | 是 | 薄 / 中 / 厚 |
| 领型 | 下拉 | 否 | 可填「不适用」「不确定」，入库归一为 null |
| 材质 | 下拉 | 否 | 可填「不确定」，入库归一为 null |
| 季节 | 只读 | 否 | 由厚度推导展示，不参与求解 |

**尺寸（条件显示）**

- 外套 / 夹克 / 西装 / 西装套装：衣长、肩宽、胸宽、袖长（4 项，必填）。
- 裤子 / 牛仔裤 / 短裤：裤长、平铺腰围、平铺臀围、裤口宽（4 项，必填）。
- 上衣（T恤 / 衬衫 / 卫衣 / 毛衣 / 针织）：衣长、肩宽、胸宽（必填）+ 袖长（选填），衣长排第一项。
- 鞋：欧码 EU 鞋码（必填，单位「码」，步进 0.5，区间 30–50）。
- 其他品类（配饰等）不显示尺寸。
- 全部手量平铺尺寸，长度类单位 cm、保留 1 位小数；**腰围、臀围、裤口存的是平铺半围，不乘 2，系统比较时自动 ×2**。量法见 `08-量衣与填表教程`。M1 不做照片估尺寸。
- 上装缺衣长、肩宽或胸宽只能存草稿；缺袖长仍可入库，只是不判袖长。鞋缺鞋码只能存草稿。
- **鞋码 M1 只存档**：详情页显示「42 码」，不参与任何规则，组合结果不受影响。

**保存**

| 情况 | 主按钮 | `status` | 是否参与求解 |
|---|---|---|---|
| 必填齐全 + 条件尺寸齐全 | [保存并入库]（无照片时文案为 [无图入库]） | `confirmed` | 是 |
| 必填齐全但条件尺寸缺失 | [保存为草稿] + 提示缺哪几项 | `draft` | 否 |
| 必填未齐 | 禁用，列出缺项 | — | — |

- 次按钮 [存草稿] 只在主按钮是确认动作（[保存并入库] / [无图入库]）时出现；尺寸缺失时主按钮本身就是 [保存为草稿]，不再叠加一个重复的次按钮。
- 保存后给 [继续录入] [查看衣库]。
- 草稿保存成功的文案明确写「暂不参与搭配」。补完入口在 `/item/:id`：草稿详情页的主按钮是 [补完属性]，录入页不重复做补完表单。
- 用户主动归档走 `/item/:id`，不在录入页出现。

> **删除按钮不存在。** 原图是我的真实衣柜，任何情况下不通过界面删除文件；归档只改 `status`。

### 4.3 `/closet` 衣库

- 一次取回全部单品（含 `draft`、`archived`），筛选、排序、分组都在前端做。
- 两列网格：单品图 `object-fit: cover` 裁切 + 名称 + 状态点；无图用品类占位块。
- 顶部筛选：全部 / 上装 / 下装 / 鞋 / 外套 / 配饰，chips 横向滚动，360px 不挤压。
- 排序：最近录入（按 id 倒序）/ 最久没穿（`last_worn_at` 为空的优先，其次日期升序）。
- 分组顺序：
  1. 草稿组置顶，标题「待补完 · 暂不参与搭配」，卡片带草稿标签；
  2. `confirmed` 两列网格；
  3. `archived` 放底部折叠组「已归档 N 件」，不与主列表混排。
- 卡片可点进 `/item/:id`；草稿、可搭配、已归档三组都可点。卡片用按钮语义，保留 `aria-label`。
- 右下角悬浮 [+ 录入]。
- 空状态：衣柜为空 → 「衣库还是空的」+ [录入第一件]；筛选后无结果 → 「这个分类还没有衣服」+ [查看全部]。
- 加载时骨架网格；请求失败给错误横幅 + [重试]。

### 4.4 `/item/:id` 单品详情

- 大图 + 缩略图条（多于 1 张时显示），点缩略图切换大图，当前项 `aria-pressed`；无图用品类占位 + 「无照片」徽标。
- 全部属性；颜色、季节、领型、材质为只读展示。
- 尺寸区按品类显示；没量的项写「未量」，草稿项高亮缺的尺寸；鞋码显示为「42 码」。
- 最近一次穿着日期显示为「今天 / 昨天 / N 天前 / 日期」，从没穿过写「还没记录」。**M1 不显示累计次数**：反馈没有单件穿着流水，加统计需要改 schema，留到 M2。
- 已确认项：主按钮 **[用它搭配]** → `/anchor/:id`；次按钮 [编辑]；文字按钮 [归档]。
- 草稿项：主按钮 [补完属性] → `/item/:id/edit`；同样可归档。
- 归档项：不参与搭配，主按钮 [重新启用]；按尺寸齐缺自动回到 `confirmed` 或 `draft`。
- 归档二次确认用页面内确认条，文案「归档后不参与搭配。照片不会删除。」，不使用浏览器 `confirm`。
- 编辑可改全部属性与尺寸；**已有照片只读**，不提供替换、删除、排序或改封面；可继续追加新照片，含已有图总数不超过 6 张。无照片的单品可在编辑页补第一张。

### 4.5 `/outfits` 组合浏览

**上下文栏（吸顶）**

```
场合  [日常] 旅游  见人        27°C 体感 · 多云   [恢复天气]
```

- 场合默认 `日常`；温度默认来自默认地点的实时体感温度（`apparent_temperature`）。
- 手动 ± 后覆盖天气，出现「已手动调整 · 恢复天气」；恢复后回到天气值。换页重新挂载即恢复天气。
- 天气取不到时退近 10 年同期值，文案写「离线 · 近十年同期体感」（只有均温时写「同期均温」）；仍取不到则用 22°C，提示「天气没取到 · 体感可手调」。
- 没有地点：提示「还没设置地点」+ [设置地点]，温度先按 22°C，可手动调。
- 降水接入 `is_rainy`：实时天气为雨/雪/阵雨/雷雨时，鞋类软规则 `R-SHO-03` 生效；离线同期值不含降水判断。
- 右上角 [换一批]。

**组合卡**（全站复用，见第五节）

- 默认展示 5 套，底部 [再看 5 套] 直到 N=10（02 的 4.5）。
- `relaxed > 0` 时，列表顶部显示横幅：

```
没有完全合规的搭配，以下为放宽 1 档后的结果。
```

- 没有合规组合、放宽到顶仍为空 → 整页空状态：

```
这个条件下配不出组合。
瓶颈：下装只有 3 条
[看看缺口诊断]
```

- 批量 [换一批]：对当前已展示但未操作的卡片记 `ignore`，然后重新取下一批。

### 4.6 `/anchor/:id` 锚定

- 顶部固定锚定单品：缩略图 + 名称 + "正在用它搭配" + 最近穿着。
- 保留场合与体感温度栏（与 `/outfits` 同一组件、同一套天气/手动/离线状态）：锚定求解同样依赖 `Context`。
- 下方与 `/outfits` **完全相同的卡片组件与排序**（02 4.2：规则与评分路径必须相同）。
- 锚定项是草稿 → 不求解，显示 [先补完这件] → 编辑页；已归档 → 不求解，显示 [查看详情]。
- 无结果 → "这件衣服目前配不出合规组合"，并给出放宽后的前 3 套（不再展开更多）+ 缺口提示。

### 4.7 `/today` 每日建议

- 顶部天气条：地点、天气、体感温度、是否降水。四种状态：
  - 实时：`深圳 · 多云 · 天气体感`
  - 离线：`离线 · 近十年同期体感`（均温回退写「同期均温」）
  - 未设地点：`还没设置地点` + [去设置]
  - 取不到：`天气没取到 · 体感可手调`
- 一张组合卡，动作只有两个主按钮：[今天穿这套] [再换]。
- 解释区**默认展开**：卡片直接显示结论、2–3 条原理的本套证据、注意事项与风格推断。今日页一天只看一套，展开不会造成列表过长；组合页与锚定页默认收起。
- 卡片上方一行状态：左边 `今日第 N 套`，右边按 `has_more` 写 `再换还有别的` 或 `再换没有别的了`。**一次只展示一套是产品口径，不是求解只算出一套**；这一行负责把「后面还有没有」说清楚。
- 「再换」＝对当前这套记 `swap`，再取下一套（跳过今天已看过的位置），不是重新求解。和 `/outfits` 的「换一批」不是同一个动作。
- 卡片下方一句话随状态变化：
  - 还有备选：`一次只推一套，省得你挑。不合适就点「再换」。`
  - 没有备选：`一次只推一套。这个条件下没有更多不同组合了，想换方向就改上面的天气或场合。`
  - 已采纳：`已记下：今天穿这套。明天会从别的组合里挑。`
- 翻到末尾 → 空状态「再换没有更多了」+ [回到第一套]，正文说明已经看过几套。
- 一开始就无解 → 区分两种原因并给可点的出口：槽位凑不齐（`candidate_count == 0`）→ [去衣库加一件]；有槽位组合但都过不了必选规则 → [看缺口诊断]。
- 采纳后：卡片变为"已记录 · 今天穿这套"，按钮禁用，`last_worn_at` 写入当天。
- 推送开关（Web Push）**本轮未做**，页面不摆假开关；延后到独立一轮（需 HTTPS/secure context 与订阅持久化）。
- 当天没有操作，次日首次打开时补记一条 `ignore`（02 的弱负信号）。这条规则在后台执行，页面不用「明天会记成没选」来给用户压力。

### 4.8 `/gaps` 缺口诊断

- 入口：`/outfits` 顶部的「缺口」文字按钮；`/outfits` 放宽到顶仍无结果时的空状态按钮。**底部页签是 衣库 / 组合 / 今日 / 我的 四列，缺口页不占页签。**
- **没有上下文栏。** 诊断固定按四个温度带全局算一次，不跟当前天气走；切换场合或温度不会改变这一页。
- 五个区块，顺序固定，区块之间不合并排序：

1. **温度覆盖** — 四条横条：`<10°C 13 套` / `10–18°C 31 套` / `18–26°C 71 套` / `≥26°C 49 套`。低于 10 套标琥珀色，并写「两周内会重复」；横条上有一条细刻度标出 10 套下限，刻度不切断横条。
2. **瓶颈** — 最多 2 张。每张：槽位 + 件数 + 依赖度；同一个单品同时压两个槽位时只出一张卡，槽位写成「中层 / 外层」。例：

   ```
   外层只有 2 件（中层 4 件，同一批夹克顶两个槽）
   冷天 13 套里有 7 套用它，删掉剩 6 套（-54%）
   ```

3. **穿不进组合的单品** — 最多 3 条，每条：单品名 + 主因规则的一句话，例（示例数据）：
   `亮橙卫衣 —— 正式度 1，与库内 90% 单品跨度 >2`。
   没有就明确写「没有穿不进任何组合的单品」，不留空区块。真实 18 件当前就是空态。
4. **场合** — 三个场合各一行：`见人 最高正式度 2.50 / 目标 3.5–4.5 · 0 套达标`，后面接卡住的槽位和最低配置：`至少需要正式度 ≥4 的内搭 / 下装 / 鞋各一件`。文案不能写成「无解」——组合出得来，只是不合场合；也不能写「补一件就行」。
5. **补齐模拟** — 最多 2 张，固定句式：

   ```
   若补一件中性色薄直筒裤：
   13/31/71/49 → 16/45/96/66 套（冷/凉/暖/热），合计 +59 套
   ```

   **没有购买链接、没有「买」按钮、没有品牌与价格。** 数字必须是全量重算的精确值，单带为负时照实显示负号。补齐卡只来自瓶颈槽位，场合缺口不在这一块模拟。

**空状态与错误**

| 情况 | 显示 |
|---|---|

### 4.10 `/theory` 搭配原理

只读参考页，不进入底部页签；从「我的 → 搭配原理」进入，返回「我的」。

- 顶部一句：「解释只使用这里列出的原理；不在代码里的理论不教。」
- 按 `视觉 → 色彩 → 合身 → 层次 → 社会 → 材质 → 图案` 分组，每组若干原理卡。
- 每张原理卡：标题、主张、为什么、怎么自己看、适用规则 ID、依据等级（A/B/C/D）、来源、状态徽标。
- 状态徽标：`生效` / `条件生效` / `结构底线` / `边界` / `当前数据不足`；`当前数据不足` 不隐藏，明确说明「当前衣柜无法计算」。
- 底部「数据不足，暂不计算」：主题、为什么、需要补什么；与正文视觉区分，不做得像可点功能。
- 静态内容，无写接口、无收藏、无进度、无测验。

| `EmptyState` | 一句话 + 一个出口按钮 | 所有列表页 |

**`OutfitCard` 的交互约定**

- 点单品图 → 进 `/item/:id`（不直接划掉，避免误触）。
- 划掉单品：点 [划掉一件] 进入选择态，单品上出现减号，再点一次确认。
- 默认精简：只显示 `explanation.headline` + 前 2–3 条原理的标题与本套证据；点 [为什么] **就地展开**，不跳页、不弹窗。
- `/today` 的卡片默认展开；`/outfits` 与 `/anchor` 默认收起。收起时不渲染长文本，展开后再渲染。
- 展开后依次显示：全部原理（为什么 / 下次怎么看 / 等级 / 来源）、注意事项、风格标签与推断依据、数据缺口。
- 原理上限 5 条（同一轴最多 2 条，合身至少预留 1 条），注意事项 ≤3 条，数据缺口 ≤2 条；缺数据的规则不出现，也不补空话。
- 风格标签旁固定显示「推断」徽标，点开显示依据与「不参与评分」说明。
- `level > 0` 保留「放宽 N 档」徽标；展开后由注意事项说明具体是哪条规则、为什么。
- `explanation` 缺失时，把 `reason` 作为**一整段**显示，不再按 `；` 拆成列表，避免放宽前缀被拆碎。
- 可访问性：展开按钮 `aria-expanded` / `aria-controls`，展开区有 `id`；来源链接有可读文本。

## 六、反馈语义

| 动作 | `signal` | 附加数据 | 界面表现 |
|---|---|---|---|
| 今天穿这套 | `adopt` | `outfit_hash` | 卡片变灰并标"已穿"，写 `last_worn_at` |
| ♡ 收藏 | `favorite` | `outfit_hash` | 图标填充，可重复点但不重复记 |
| 再换 | `swap` | `outfit_hash` | 当前卡片滑走，下一张上来 |
| 划掉一件 | `veto_item` | `outfit_hash` + `garment_id` | 该组合移出列表，重新取下一套 |
| 批量换一批 | `ignore` | 已展示未操作的每张卡 | 无视觉反馈 |
| 当天未操作 | `ignore` | 当日建议的卡 | 次日补记，无视觉反馈 |

- 所有反馈都写 `hit_rules`，用于 M4 归因。
- **不做显式评分（1–5 星）。** 收集率会趋近于零。

## 七、状态矩阵

| 状态 | 触发 | 界面 |
|---|---|---|
| 首次无数据 | 衣库为空 | 空状态 + 录入入口 |
| 首次未设置 | 无 profile 且无地点，从 `/closet` 进入 | 跳 `/setup`；跳过/完成后不再自动进入 |
| 未设地点 | `location` 为空 | 天气条「还没设置地点」+ 去设置；体感按 22°C 可手调 |
| 天气失败 | 实时天气不可用 | 退同期气候；仍不可用则「天气没取到」，求解照常 |
| 草稿 | `status=draft` | 灰点 + 「待补完 · 暂不参与搭配」 |
| 无照片 | 封面与追加图都为空 | 衣库与组合卡显示品类占位 / 「无图」，不阻塞入库 |
| 放宽 | `relaxed>0` | 顶部 `RelaxBanner`，每张卡也有小标记 |
| 零结果 | 放宽到顶仍为空 | 空状态 → 缺口诊断 |
| 离线 | 天气请求失败 | "离线 · 近十年同期体感"，求解照常；不含降水判断 |
| 请求失败 | 后端 5xx | 卡片区显示 [重试]，不清空已有结果 |
| 锚定项是草稿 | `status=draft` | 不求解，引导补完 |
| 归档 | `status=archived` | 不参与搭配；衣库折叠组可见，详情只给重新启用 |

## 十、验收

1. 所有页面在 390×844 与 360×800 下无横向滚动、无按钮出屏。
2. 从拍照到入库，熟练后 ≤30 秒/件；首次 ≤60 秒。
3. 锚定结果 3 秒内出现（对应 `03` 验收第 7 条）。
4. 每个空状态都有可点的出口。
5. `relaxed`、`草稿`、`无图` 三类标记在界面上真实可见。
6. 组合卡划掉需二次确认，不误触；衣库卡片与组合卡单品图可点进详情，减号不触发跳转。
7. 首次从 `/closet` 进入会走 `/setup`，跳过或完成后不再自动进入；深链不被劫持。
8. 组合、今日、锚定的体感默认来自天气，手动 ± 可覆盖并恢复；未设地点/离线/失败都有出口。
9. 切换默认地点后温度与搭配结果随之变化；`/settings` 可管理地点/身材并导出不含照片的 ZIP。
10. **验收方式：browser-harness 截图 + vision skill 分析**，覆盖首屏、滚动中段、底部；不靠阅读代码推断布局。
11. 一件衣服最多 6 张照片，第一张标「封面」；详情页可切换查看；已存照片在任何入口都无法删除。
12. 颜色可从预设、系统调色板、照片点选三处得到；照片取样为 5×5 平均，点纯色图得到对应 HEX。
13. 上衣（含毛衣/针织）缺衣长只能存草稿；鞋缺欧码只能存草稿；详情页鞋码显示「42 码」。
14. 每张组合卡都有结论与 1–5 条原理；`/today` 默认展开，`/outfits` 与 `/anchor` 默认收起；展开后就地显示，不跳页、不弹窗。
15. 每条原理都能追溯到规则 ID，并显示依据等级与来源；风格标签带「推断」徽标；放宽、扣分、上下文偏差、缺数据四类情况在展开区可见。
16. `/theory` 从「我的」进入，可浏览 18 条原理、五种状态徽标与「数据不足」清单；返回「我的」。
